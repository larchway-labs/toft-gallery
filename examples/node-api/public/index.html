API

Six routes. Three of them need a role, and the refusal says which one it saw and which one it wanted — because “forbidden” is the least useful sentence in software.

RouteNeedsWhat
GET /api/tasks anyone ?done=, ?owner=, ?lane=. Carries the caller's role back.
POST /api/tasks editor Add one.
PATCH /api/tasks/{id} editor Close, reopen or rename.
DELETE /api/tasks/{id} editor Remove one.
GET /api/platform anyone What the platform told this app.
GET /healthz anyone Real uptime and a real count.
An unknown path is a JSON 404 naming the method and the path, not an HTML error page. An API that answers a machine with a stylesheet is an API that will be debugged twice.

Reaching it as a machine

# An app key reaches these routes the same way a browser does.
curl -H "Authorization: Bearer toft_..." \
     https://toft.example/apps/node-api/api/tasks
A key can carry a role. An owner or editor of this app may mint an toft_ key describing their machine client as viewer or editor, and it satisfies the gate exactly as a person with the same word does. That is the point of the word — the caller may do what it says — and it is why nothing here pretends to tell you a human is in front of it.

The caller's role

Six words and no seventh:

Verified in this process. No round trip, no administrator switch, and it is on every forwarded request whether anybody configured anything or not. The key is derived per app and per workload start, so a blob minted for another app fails here.

Platform headers on this request

Presence only. The role blob is a credential for 120 seconds, and a page that printed one would have published it.
