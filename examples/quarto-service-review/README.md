# Service Review

Ten services, 148 incidents and one quarter — rendered **once, at deploy time**,
and served as the document that fell out.

A Quarto document whose engine is **knitr**, which is what makes it R rather
than Python. Base R graphics, no ggplot2, no chart library, no CDN.

## Why this one exists

The Toft gallery has three R apps that are servers — a Shiny model, a
plumber API, and nothing in between — and two documents. This is the second
document, and it is here to show the half of Quarto that an R Markdown report
cannot do:

| | |
|---|---|
| **A contents rail** | Numbered sections, resolved automatically, on the left. |
| **Cross-references** | `@fig-availability` and `@tbl-availability` are the same nine numbers twice, and neither can be renumbered by hand into disagreeing with the other. |
| **Callouts** | Note, tip and important, and one of them collapses. |
| **Tabsets** | Three views of the same quarter without three pages. |
| **Folded code** | Every chart shows the code that produced it, closed by default. |

Quarto is what to reach for when the output is meant to be read by somebody who
did not write it. R Markdown is what to reach for when it is not.

## How Toft decides this is knitr

In this order:

1. `[notebook] engine = "knitr"` in `toft.toml`
2. `engine:` / `knitr:` in the document's YAML header
3. a fenced ```` ```{r} ```` chunk
4. otherwise **`notebook` in the Python family**

Rule 4 is the compatibility rule, and it means no app that deployed before R
existed changes framework. This repository declares it by rule 1 *and* satisfies
rules 2 and 3, so a future edit to any one of them cannot quietly move it.

## The two things worth knowing before you deploy one

**The chunks run at deploy time with this app's whole environment**, and
whatever they print is in the published document. Nothing is redacted — the
platform cannot know which cell output is a secret — and on a public app,
"published" means the internet. The build log lists the variable *names* that
were exported, never their values. This is the point of the framework and its
sharpest edge, and Toft states it rather than gating it.

**Quarto is not bundled.** On an install without it, a `.qmd` fails the deploy
naming `QUARTO_BIN` — refused, never quietly rendered with nbconvert. An
operator installs it on the machine that builds, or runs the `<version>-quarto`
image tag.

## The rest of the shape

- **`renv.lock` is committed**, which is not optional in spirit: without one
  nothing is installed, the deploy succeeds, and the app fails at its first
  `library()` call. Its Dependencies tab would read *not enumerable* rather than
  *no dependencies*, and such an app can never be blocked by the install's
  dependency policy.
- **Nothing is re-rendered by a restart.** A wake, a crash restore or a repair
  serves the document this release was deployed with. Only a deploy produces a
  new one — and a schedule on the app's Overview tab makes that deploy happen on
  a cron expression, which is a full re-clone and every chunk from the top.
- **A failing chunk fails the deploy, and the release already serving stays up.**
- **A missing data file is a first-class outcome**, not a crash: the report says
  so on its own front page instead of leaving somebody to find it in a build log.

## The data

`data/incidents.csv` and `data/services.csv`, committed, generated by
`tools/make-sample.py` from a fixed seed. Point the report somewhere else with
`REVIEW_DATA_DIR`.

## Running it

On Toft: paste this repository's URL. It needs an install with Quarto.

Locally:

```bash
Rscript -e 'renv::restore()'
quarto render report.qmd
python3 tools/make-sample.py      # to regenerate the CSVs
```

## The house style

The look is the [Toft Example Kit](https://github.com/larchway-labs/toft-gallery/tree/main/kit),
with `static/quarto.css` as the layer between it and Quarto's own HTML — the
title block, the contents rail, callouts, tabsets and folded code. It never
redefines a kit token; that is the rule for every example's own stylesheet in
this gallery.
