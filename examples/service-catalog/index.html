    What a static app has to know

    Relative URLs work; root-absolute ones do not. This app is served under /apps/{slug}/, so assets/styles.css resolves and /assets/styles.css asks the platform for a file it does not have. Toft warns in the build log and never rewrites.
    Entry
    index.html, unless [static] entry names another
    Root
    the release, unless [static] root names a subdirectory
    Fallback
    off — only a client-routed app needs it, and on by default would turn every missing asset into an HTML document
    Never served
    anything beginning with a dot, toft.toml, ecosystem.config.json. 404, not 403
    Unmatched
    404.html, which is the page in this repository

    Detected last, and on purpose

    A repository is static only when it carries none of package.json, requirements.txt, pyproject.toml, Pipfile or go.mod. That list is the specification, and it exists because a Vite repository detected as static would deploy successfully and serve a blank page forever.

    Nothing is installed and nothing is compiled. The workload is a serve-static subcommand of a binary that is already there, over an image under 10 MB. Conditional requests and Range work, so a large PDF behaves. There is no compression, no fingerprinting and no cache headers: the release is the site.

    Everything on this page comes from data/services.json. Replace that one file and the catalog is yours.
