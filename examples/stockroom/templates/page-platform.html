How this app talks to Toft

What it reads from the environment

PORT
the port to serve on, bound to 127.0.0.1 and nothing else
BASE_PATH
the mount prefix; the proxy strips it, so every link is written back with it
TOFT_API_URL
where the app API is
TOFT_APP_TOKEN
this app's outbound identity, rotated by every deploy
TOFT_SCRATCH_DIR
ephemeral space; wiped on deploy and restart
TOFT_STORAGE
durable mounts, when any are mapped

What it calls

GET /app/self
who this app is and what it may do
POST /app/notify/slack/file
the report PDF, into the channel its owners chose
POST /app/notify/email
the report, to addresses somebody typed here
POST /app/jobs/report/runs
start the report job now, in the clicker's name
GET /app/job-runs
the report job's runs, for the Activity tab

What Toft sends it

X-Toft-Session
an opaque per-session id — enough to tell two people's edits apart, never enough to name either
X-Toft-Act-For
an opaque blob, relayed untouched when starting a job, so the run is attributed to the person and not the app

What the report job is given instead

TOFT_JOB_TOKEN
a run's credential, accepted on the send routes while the run is in flight and nowhere else
TOFT_PARAMS
the run's params, typed and already checked against toft.toml
TOFT_SCHEDULED_FOR
the tick a scheduled run is for, never "now"
