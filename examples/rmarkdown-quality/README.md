# Data Quality Report

An R Markdown example for Toft: point it at a CSV and it renders a page
that says what is wrong with the file. Missing values, duplicate keys,
categories that are the same thing spelled two ways, numbers outside Tukey's
fences, and a histogram of every numeric column.

It ships with a sample delivery export — 1,209 rows, deliberately dirty, seeded
so it never changes — so there is a real report on screen before you point it at
anything of your own. Nothing in the document is specific to that file: the same
seven checks run against whatever `REPORT_DATA` names.

## Three things worth copying

**This is rendered once, at build time.** Toft runs `rmarkdown::render`
into `toft-render/` and serves the directory that falls out. There is no R
process behind the page — a viewer is talking to a file server — so nothing in
the document can be interactive, and **a re-render is a deploy**. If you want it
refreshed nightly, give the app a render schedule; a restart will not do it, and
neither will the file underneath changing.

**The render sees the app's environment variables, and the output is published.**
That is what lets this report read `REPORT_DATA`. It is also the sharp edge: a
document that reads a connection string and prints it has published that
connection string to everyone who can read the page. Print what the report is
about, never what it connected with.

**A missing input file is a section, not a crash.** On a fresh install the
nightly export has not landed yet, and that is normal for a while. Failing the
build makes somebody read a build log to find that out; the report says so on
its own front page instead, naming the path it expected.

## One document at the root

Toft decides which document is the app by counting the `.Rmd` files at the
repository root, so there is exactly one here. Two is ambiguous and the deploy
refuses by name. That is why `data/make-sample.R` lives in a subdirectory — and
it is worth knowing the second reason as well: a root `.R` file is scanned for
plumber annotations, so a helper script left beside the document could decide
the whole repository's framework.

## Configuration

| Variable | Required | Default | Meaning |
|---|---|---|---|
| `REPORT_TITLE` | no | `Data Quality Report` | Document title. |
| `REPORT_DATA` | no | `data/deliveries.csv` | The CSV to profile, relative to the release directory. |
| `REPORT_KEY` | no | the first column | The column expected to be unique. |
| `REPORT_MAX_ROWS` | no | `200000` | Row cap on the read. The report says when it hit it. |

## Dependencies

`renv.lock` is committed, which is what makes this deployable. Without one
Toft installs nothing, says so in the build log, and the render fails.

Only `rmarkdown` is declared; `knitr::kable` comes with it, and every statistic
is base R. The report deliberately uses no plotting or table package — a
lockfile that restores in seconds is worth more here than prettier defaults,
because a document app pays that cost on every single deploy.

## Local development

```bash
Rscript -e 'renv::restore()'
Rscript data/make-sample.R          # only to regenerate the sample
Rscript -e 'rmarkdown::render("report.Rmd", output_dir = "out")'
```

Then open `out/report.html`.

## The sample data

`data/deliveries.csv` is generated by `data/make-sample.R`, which is committed so
the file is reproducible rather than mysterious. It has missing weights and
regions, nine duplicated order ids, three spellings of `North`, six impossible
delivery durations and five costs off by a decimal point — because a data
quality report over clean data says nothing at all.

## The house style

The look is the [Toft Example Kit](https://github.com/larchway-labs/toft-gallery/tree/main/kit) —
`static/toft-kit.css`, byte-identical in every example in the gallery, with
`static/rmd.css` as the layer between it and rmarkdown's own HTML: the title
block, the floating contents rail, kable's table, and a code chunk. It never
redefines a kit token.

`theme: default` stays in the YAML because `toc_float` needs a Bootstrap theme
to float against; the kit is loaded after it and wins. The two plot colours are
`--lp-c1` and `--lp-dan-solid`, copied, so a base-R histogram matches every other
chart in the gallery.

The masthead is emitted from an `asis` chunk through `html_block()`, which strips
the indentation first — pandoc reads a line indented four spaces as a code block,
which is how a masthead ends up on the page as source.
